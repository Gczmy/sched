# sched 0.2.1 Release 说明

发布提交、完整 CI run 与产物摘要以
[GitHub Release](https://github.com/Gczmy/sched/releases/tag/v0.2.1) 为准。
候选构建会在本说明前附加来源提交；生产部署独立安排。

## 主要变化

- `linux_fd_owner` 使用独立原始 child owner，在 daemon 重启后保留真实 wait、
  rusage 与进程组清理事实，认证重连不重新启动 child。
- 增加有界的准备超时与终态保留冷配置，以及持久确认队列；每轮至多处理
  8 条历史确认，失败退避，不扫描已确认历史或删除 owner binding。
- `sched execution` 提供逐版本诊断、历史 session 摘要和已记录的 owner 连接/
  确认状态；查询保持只读，不把未知退出结果视为成功。
- `sched execution list` 增加跨任务筛选与有界实时分页；多页结果不冒充完整当前态。
- `sched capabilities --json` 与 `sched daemon check --json` 提供版本化能力与前置
  检查结果，区分声明、验证与未知；计算节点守卫保持有效。
- CI 从固定提交生成源码和默认/native wheel，附带安装说明、文件哈希、
  Python ABI、构建环境及独立安装和原始 owner wait 验证证据。

## 安装与兼容性

默认 wheel 为 `sched-0.2.1-py3-none-any.whl`，要求 Python >= 3.10，运行时无第三方依赖。
调度执行要求 Linux/POSIX。native 为可选能力，CI 分别验证 CPython 3.10、3.14 /
Linux x86_64；须核对 manifest 中的 SOABI、libc 和平台，不声明 manylinux 兼容。
从已审查的最终提交选定候选，通过校验器与 GitHub artifact digest 检查后安装，
从无关目录运行 `sched --version`、`sched --help` 并验证所需 backend。

0.2.1 写库 schema 7，只读支持 schema 1–7；已有 binding 迁移不重放历史 attempt。
`status`、`task`、`history` 的 JSON schema 仍为 1。默认 subprocess 与 `linux_fd`
FD4 v1 保持现有契约；`linux_fd_owner` 需显式配置，并由客户程序支持
`sched_execution_owner_identity/v1` FD4 封装。

## 升级与回退

生产切换需单独授权。先 drain，等待运行任务和未决启动清空，保留旧安装、配置和
经审查的兼容状态恢复点，再安装与检查。旧 writer 不能被假定为兼容 schema 7；
回退须按实际 schema 与恢复方案执行。结果未知的 attempt 和 owner binding 必须保留，
不能重放；owner 存活或清理未决时保留其原安装。

完整发布、下载验证和维护流程见 [execution-rollout.md](../execution-rollout.md)。
