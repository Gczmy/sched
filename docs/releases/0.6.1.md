# sched 0.6.1 候选 Release 说明

较大的历史实例可能超过 0.6.0 恢复点的 10,000 项范围，且旧目录权限会阻止完整备份。
此候选增加正式权限准备 CLI，并将节点树范围固定为 20,000 项。
create 仍保存和验证全部原文件；文件、数据库事实、metadata 大小及时间限制保留。
关闭点清理范围为 30,000 项，容纳新镜像和原审计，其他保留期和回退规则不变。

`snapshot permissions --dry-run --json` 给出原目录计划；计算节点执行要求
`--writers-quiesced --expect-plan <plan_sha256> --yes`。原实例、原目录 FD/inode、
配置和完整数据库事实均复核。只收紧目录的 group/other 权限，不迁移数据库、删除
任务/日志/通知、启动 daemon 或推断原 wait。中断保留已收紧目录和审计，重新预览后继续。
完整契约见[升级恢复点](../upgrade-snapshot.md)。

writer schema 仍为 25，完整只读 1–25，生产恢复点支持完整 schema 10–25。
兼容租约、CPU affinity 和 device off 行为沿用 [0.6.0](0.6.0.md)；硬隔离仍为 false。
默认 wheel 运行时零第三方依赖；native 必须匹配解释器 ABI 与 libc。

候选尚未发布或部署。固定来源、完整 CI、原始资产、计算节点验收及正式发布事实
须在完成后另行记录；不更改原 0.6.0 标签或资产。
