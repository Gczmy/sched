# sched 0.6.1 Release 说明

[v0.6.1 Release](https://github.com/Gczmy/sched/releases/tag/v0.6.1) 已于
2026-10-10 01:38:06 UTC 正式发布，固定来源为
`50e7d9817e8e77cabff99dfb5738d5c37720ba1c`。
[main push CI](https://github.com/Gczmy/sched/actions/runs/38012371711) 14/14 成功；
四份原始 CI ZIP、来源证据、发布说明及总校验和共七项资产，均已公开下载逐字节核对。
原说明和 manifest 保留构建时的候选状态，发布事实由 Release/tag 及本页补充；
本页更新不改变原标签或资产。生产目标状态须通过目标 CLI 和私有部署回执确认。

较大的历史实例可能超过 0.6.0 恢复点的 10,000 项范围，且旧目录权限会阻止完整备份。
此版本增加正式权限准备 CLI，并将节点树范围固定为 20,000 项。
create 仍保存和验证全部原文件；文件、数据库事实及 metadata 大小限制保留。
网络文件系统可显式使用 `--io-timeout-sec 300`，默认 30 秒，上限 900 秒。
原预算冻结在恢复点和窗口；后续复核与受控回退沿用原预算，不允许调大旧恢复点。
SQLite 备份及数据库事实时间限制不变。
关闭点清理范围为 30,000 项，容纳新镜像和原审计，其他保留期和回退规则不变。

`snapshot permissions --dry-run --json` 给出原目录计划；计算节点执行要求
`--writers-quiesced --expect-plan <plan_sha256> --yes`。原实例、原目录 FD/inode、
配置和完整数据库事实均复核。只收紧目录的 group/other 权限，不迁移数据库、删除
任务/日志/通知、启动 daemon 或推断原 wait。中断保留已收紧目录和审计，重新预览后继续。
完整契约见[升级恢复点](../upgrade-snapshot.md)。

writer schema 仍为 25，完整只读 1–25，生产恢复点支持完整 schema 10–25。
兼容租约、CPU affinity 和 device off 行为沿用 [0.6.0](0.6.0.md)；硬隔离仍为 false。
默认 wheel 运行时零第三方依赖；native 必须匹配解释器 ABI 与 libc。

权限准备和 I/O 预算分别通过独立 named contract 协商，旧 0.6.0 安装不会因发布获得这些能力。
修复 PR [#23](https://github.com/Gczmy/sched/pull/23) 与
[#24](https://github.com/Gczmy/sched/pull/24) 均已合并并清理分支。61 项快照回归、
独立 CLI 迁移/回退与不重复执行验收通过；对应固定来源的完整 CI 已通过。
原 0.6.0 标签和资产保持不变。
