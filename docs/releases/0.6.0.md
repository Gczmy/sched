# sched 0.6.0 候选说明

本版本尚未发布、未部署生产。基线为已发布的 [v0.5.0](0.5.0.md)，
保留其原始标签和七份发布资产。最终固定来源、完整 CI 和原始安装产物须独立核验。
默认 wheel 要求 Python >= 3.10、零第三方运行时依赖；native 必须匹配解释器 ABI 和 libc。

## 已关闭恢复点管理

新增独立合同 `sched-upgrade-snapshot-management/v1`，不改变升级窗口 v1 的回退权。
`snapshot list` 通过现有私有稳定锁只读查询，不初始化 state、控制目录或数据库；
默认 20、最多 100 行，实时 keyset 分页；metadata 总读取有 64 MiB/30 秒上限。
跨页不是一致全量快照。

`snapshot prune` 默认保留 30 天和最近 2 个未清理关闭点，先用 `--dry-run --json`
取得 `as_of/plan_sha256`。计算节点执行须沿用同参数，加 `--yes --expect-plan`。
绑定原关闭/manifest/host/state/config、完整文件集合、目录 inode、文件摘要及 mtime/ctime；
活动窗口、镜像损坏、旧关闭时间未知、链接、未知文件和漂移均拒绝。

删除前保存原 pruning 意图，中断只沿同一计划续接；移除已关闭点的镜像副本，
保留 point inode、manifest、rollback journal、永久关闭记录和清理审计。
不修改当前 DB/config、unknown 请求、execution、scope、任务、revision 或实例，
不恢复写入、启动 daemon 或复活已消费的回退权。原 v0.5.0 的无时区关闭时间不补写。
清理后 verify 缺少镜像而失败，不由摘要推断仍可恢复。
完整合同与调用方法见[升级恢复点](../upgrade-snapshot.md)。

## 学生账号兼容路线

默认严格 cgroup 检查保持不变。显式 `launch_ancestry` 与固定 `cpus_total=120`、
可选 `cpu_isolation.mode=affinity` 联合工作，声明预算不会扩大可信原 CPU 池。
兼容租约有效性、真实启动来源、当前 daemon 的 Slurm 归属和硬隔离能力分别报告。
后代继承初始 mask，但应用可主动放宽；始终保留 `hard_isolation:false`。

新增[联合验收入口](../../tests/run_launch_affinity_accept.py) 检查真实原 job/step/anchor、
两 CPU 私有池、非重叠 claim、worker/后代、补位、取消、两种 native backend 原 wait。
故障选项涵盖控制器失败/实际 helper 超时、私有 daemon 挂起的证据过期、
fixture 身份/租约变化、私有 daemon mask 漂移，以及原持久 owner 的崩溃重连。
2026-10-09 已从用户指定的既有计算租约，以固定源码 `6420b3a`、系统 CPython 3.12.3
独立构建 native，完整联合入口通过并确认私有 daemon 停止、活动 CPU claim 清空。
实机发现并修复了 claim 选择时漏读原 anchor 的阻塞；每次选择重新观察原 anchor，
新鲜不可读/漂移不会使用缓存 valid 决策放行。这里记录固定源码的运行事实，
最终候选仍须按对应来源独立核对。
fixture CANCELLED 不算真实原 Slurm 租约结束；无 cpuset/BPF 权限时硬隔离专项暂停。
具体证据和剩余项见[兼容路线](../student-compatibility.md)。

普通任务的父进程与 wrapper 发布相同强身份时，验证读取可能遇到已被另一方
替换、解除链接的旧 inode。现在只在该情形重开路径一次，仍验证新记录的强身份；
外来身份、两次连续竞态、硬链接或不可读记录继续拒绝。确定性回归覆盖同身份
竞争、外来身份替换及重开次数上限，不以放宽 marker 安全检查解决误报。

## 兼容与生产边界

writer schema 25、完整只读 1–25；默认 status/task/history 与健康 JSON 不变。
永久关闭记录新增可选 epoch，旧记录不迁移；新管理命令独立协商，旧客户端无此能力。
v0.4.0/schema 10 writer 不能回接新写库；回退仅限仍满足原绑定的未关闭升级窗口。
生产维持既有运行，切换在另行安排的维护窗口进行，不因候选构建而排空或安装。
