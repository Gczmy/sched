## 通用反馈修复

配置阶段拒绝显式节点 GPU 池与项目硬亲和无交集；不自动扩大 GPU 池或接管外部进程。
逐项产物诊断区分系统错误与内容不匹配，新增 json_equals 和不可变首次验证证据。
仅产物复验通过 task/instance CAS request 追加事件，显式 settle 才能结算；不训练、
不删除产物、不覆盖原失败。缺少原 wait/cleanup 或来源变化时不能补判成功。

默认批次失败策略仍为 freeze；显式 continue_independent 放行独立任务而不绕过依赖。
精确依赖、任务 DAG/路径和受审计更新绑定原实例、批次和版本，不随同名新批次漂移。
精确任务事实与成组 pending-only cancel 保留启动/未知尝试守卫；替代 campaign、
科学 lineage、跨节点排班和 ETA 仍由客户层维护，不进入 daemon。

不可变 allocation 和分层事件关联原执行、监控、产物与资源事实，不推断科学 worker。
admission explain 复用资源判断并保留观测时效；opt-in 存储准入检查空间、inode、
可知用户 quota 和控制面余量，不自动删除产物，也不承诺实际写盘永不耗尽。

## 租约与可选执行约束

持久保存白名单启动来源，持续校验原 Slurm allocation；unknown 默认停新派发，
确认 invalid 后锁存，running 正常结束，不自动绑定后来创建的租约。
默认 membership=cgroup；显式 launch_ancestry 校验冻结的真实启动链、原 shell/stepd
和精确 step 跟踪，未知仍暂停。兼容 valid 不证明后台 daemon 当前被 Slurm 跟踪或硬隔离。
CPU auto 取可信 Slurm/affinity/可选上限的保守值，0 保留“不限制总声明预算”。

CPU affinity、委派 cpuset、设备 BPF/controller、原 NVIDIA/MIG 映射和被动根健康
已随本版本提供 opt-in 实现，默认 CPU/device isolation 关闭。亲和不是不可越界限制；
正向 cpuset/BPF/设备 scope 故障矩阵与 MIG 精确权限验收尚未完成。
默认隔离关闭的真实 CUDA 恢复与启动祖先 CPU/CLI 证据不替代这些硬隔离证据。
旧 owner 重连只观察原尝试，不重新 start；未知资源/清理事实不凭 PID、日志或产物补造。

## 升级与交付边界

writer schema 25，完整只读 1–25；公开 status/task/history JSON 仍为 schema_version 1。
新增独立接口按 named contracts 协商，identity 用于实例绑定，不代替能力查询。
迁移不回填历史分配、wait、依赖或租约事实；已发布 0.4.0（schema 上限 10）及其他
旧 writer 不能回接新写库，不能降低 user_version、删记录或重新生成实例进行回退。

生产切换需独立授权，先现场查询、无损排空、取得并验证升级恢复点，再切换独立安装。
持久 [升级窗口恢复点 CLI](../upgrade-snapshot.md) 已随本版本发布；仅支持尚未恢复写入/派发
的受控回退，保留未知事实且不自动启动 daemon。完整验收和生产恢复点仍须分别验证。
流程见 [execution rollout](../execution-rollout.md)。候选包、正式发布和生产切换分别记录。
