# sched 0.3.0 Release 说明

本说明用于 0.3.0 交付。最终来源、完整 CI、包哈希和实际发布事实以 GitHub Release、
tag 与 release-evidence.json 为准；本文不表示生产已经升级。

## 主要变化

- 显式 checkpoint/smoke 协议绑定代码、输入和任务配置。原子保存有界 JSON 进度；
  smoke 需真实成功退出及匹配 receipt。客户负责算法、精度和科学验证。
- 显式恢复策略只在原始退出或清理事实得到确认后创建新 job version/attempt。
  普通组先完成，OOM 延后 FIFO、冷却和 lineage 跨重启保留；未知 wait 不授予重放权。
- 项目 gpu_admission 默认要求固定 12 GiB 空闲显存，可显式许可已知外部占用。
  完整 GPU 探测、峰值预留、容量覆盖和启动前重检防止在不确定状态下派发。
  恢复可配置非递减门槛、持久无进展通知及等待中的停止期限，默认不限重试和等待。
- daemon foreground 提供整个节点一个 supervisor；只有真实子进程 wait 才允许
  意外退出重启。stop、signal、drain、未知 lease 与持久 owner 原始 wait 语义保留。
- status/task/history 的 JSON schema 与 wait_reason 枚举保持不变；恢复详情由
  独立 recovery --json 查询提供，配套客户端继续使用公共 CLI。

## 验收与安装

默认安装与回归覆盖 Python 3.10–3.14；native 构建、安装和真实执行覆盖
CPython 3.10/3.14 × Ubuntu 22.04/24.04 / Linux x86_64。
2026-10-02 的隔离真实 GPU 验收在 RTX A5000 / Python 3.12.3 源码 native 构建上
通过 8 项检查：实测 11.898 GiB 阻止派发、12.148 GiB 允许；实际 CUDA OOM 后
等待 20 GiB 门槛；A → B → C → A → A FIFO 无重复结果；显存预留；daemon SIGKILL
保留同一 attempt；worker SIGKILL 保留 rc=-9 并新版本恢复；GPU 禁用与
drain/resume/stop。程序实际执行 PTX kernel，不依赖训练框架；原始证据私有保存。

默认 wheel 不含 native extension，运行时无第三方依赖。native wheel 须按包内
Python ABI、平台和实际 libc 选择，不声明 manylinux 通用兼容；CUDA 验收环境
中的源码构建不自动扩大正式二进制资产支持范围。

## schema 与回退

新写库原子升级到 schema 9，只读完整 schema 1–9，查询不迁移。
0.2.2 的 schema 7 二进制不能回接新写库；不能删除历史尝试或恢复记录来回退。
部署前保留旧安装、配置及经正式备份流程取得的恢复点；排空并确认所有运行和
未决 owner 后才能按审查过的方案切换。见
[维护与回退](../execution-rollout.md)。正式发布和生产切换分别安排。
