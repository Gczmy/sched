# sched 0.3.1 Release 说明

最终发布来源、完整 CI、原始资产和校验和以 GitHub Release、tag 与
release-evidence.json 为准。发布不表示生产已经升级。

## 主要变化

- 修复 SQLite DB/WAL/SHM 权限处理额外 open/close 释放进程 POSIX 锁的问题。
  权限检查使用不跟随符号链接的元数据操作；私有 DB/WAL 快照在独立子进程中复制。
- 事务失败记录阶段、进程和 SQLite 错误码；仅在精确 SQLITE_BUSY 且事务仍活动时
  有界重试 COMMIT，不重放事务体。协议错误、未知结果和外部副作用不自动重试。
- 保留 `sched --version`，增加 `sched version` 与 `sched version --json`。
  无配置或配置损坏时仍能查询当前代码版本及 schema 兼容范围，不打开状态数据库。

Linux 回归覆盖锁保持、竞争写入、嵌套连接、同进程快照、权限拒绝和事务失败边界。
独立 wheel 安装验证版本查询在配置损坏时不创建状态。详细机制见
[SQLite 锁处理](https://github.com/Gczmy/sched/blob/main/docs/sqlite-lock-safety.md)。

## 安装与升级

默认 wheel 无第三方运行时依赖，要求 Python >= 3.10；不含 native extension。
正式 native 资产范围以 CI manifest 的 CPython ABI、Linux x86_64 和 libc 为准，
不声明 manylinux 通用兼容。其他 ABI 须从固定来源单独构建和验收。

本版本与 0.3.0 使用相同 schema 9，只读支持完整 schema 1–9。
从 schema 4 或更旧版本完整升级时，新 writer 仍会迁移数据库；不能把整个新 state.py
当作旧 schema 的局部回补。先排空、核对历史启动与执行尝试、保存旧安装及经过验证的
恢复点，再切换独立安装。新写库不能直接回接旧 schema 4 程序；回退必须遵守
[维护与回退](../execution-rollout.md)。
